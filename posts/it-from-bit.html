It from Bit

John Wheeler proposed it from bit: the physical world may be built on information, on the yes-or-no answers we get from measurement. Wheeler’s essay

I want to ask a related question. What becomes easier to see if we view the universe computationally?

111111111

Nine ones. Add a million more and the description barely grows: a rule and a number.

101010101010101

Alternate ones and zeros. Same idea.

11010101000100

No obvious rule. Maybe a short program generates it. Maybe the shortest description is the string itself.

Kolmogorov complexity measures this gap between how much data something contains and how little it takes to describe it: the length of the shortest program that outputs the string. For repeating patterns, that program stays the same size however long the string gets:

C(1n∣n)=O(1),C((10)n/2∣n)=O(1)C(1^n\mid n)=O(1), \qquad C((10)^{n/2}\mid n)=O(1)

Most strings, though, can’t be compressed. There aren’t enough short programs to go around:

Pr⁡[C(x∣n)<n−d]<2−d.\Pr[C(x\mid n)<n-d]<2^{-d}.

Fewer than one string in 1,024 can be shortened by ten bits. Fewer than one in 21002^{100} by a hundred. This counting argument is the incompressibility method.

Here is the part I find most interesting. Describing every string of length nn one by one costs about n2nn2^n bits. Describing all of them together is trivial:

Enumerate every binary string of length nn.

But generating everything identifies nothing. Picking out one string still takes an nn-bit address.

A lot of what we call insight lives here: finding one rule that covers many cases, so we can carry something smaller and use it somewhere new. A pattern is useful when it predicts what we haven’t seen yet.

I think everything we say exists is a string of bits, together with an algorithm that makes those bits legible: one that maps them onto the bits we already know. That, to me, is what knowledge is.

Patterns also have to survive. Bits live in physical things, and physical things get disturbed. Redundancy protects them: encode a zero as 000 and a majority vote fixes a single flipped bit. Shannon showed how far this goes: reliable communication is possible over any noisy channel, up to its capacity. A Mathematical Theory of Communication

Compression removes repetition. Redundancy adds it back so we can recover from damage. Living and engineered systems need both: a compact account of the world, and a reliable way to keep it.

This brings me to AGI and ASI.

For a language model, prediction is compression. Better probabilities mean shorter encodings. Language Modeling Is Compression Scaling laws show that more parameters, data, and compute keep lowering prediction loss. Read through this lens, models are compressing more and more of the structure in their data. Scaling Laws for Neural Language Models; Training Compute-Optimal Large Language Models

Which brings back the collection of all strings. Somewhere in it are a better experiment, a material we haven’t made, a solution to a problem we can’t yet solve. So are countless convincing mistakes. Knowing an answer exists doesn’t tell us how to find it, recognize it, or make it work in the real world.

Picture knowledge as a sphere. Each ring outward is one bit longer, so it holds twice as many possible strings as the ring before it. What we know is not only the strings but the paths to them.

Say we get superintelligent AI, and it is very good at exploring paths: taking all the paths we know and extending them. Every added bit still doubles what is left to explore, and the paths we know may not be dense. How dense is the set of things we know?

That is what I want to understand about scaling. Even if we become very good at discovering paths, how does the knowledge we gain scale with the compute we apply? What is the heuristic? When does better prediction become discovery? And what else does a system need to turn a discovery into something that works?
